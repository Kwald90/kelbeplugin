# Fishtape iOS app

The iOS app is the PWA in `electrical-app/` packaged with [Capacitor](https://capacitorjs.com) 8,
plus four native plugins of our own: `FishtapeMeasure`, which gives Wire Runs a real ARKit tape
measure (Safari on iPhone and iPad has no WebXR AR), `FishtapeKeychain`, which keeps the sign-in
token in the iOS Keychain, `FishtapePrint`, which makes every Print button work, and `FishtapeGeofence`, which notices job-site arrivals and departures while someone is clocked in (see [FishtapeGeofence](#fishtapegeofence)). It is built on
Kelvin's Mac over SSH.

| | |
| --- | --- |
| Bundle ID | `com.fishtapehq.app` (registration still to do, see [Signing and TestFlight](#signing-and-testflight)) |
| API | `https://tgelectrical.truecollarbuilt.com` (staging) by default; see [API origin](#api-origin) |
| Name on the home screen | Fishtape |
| Capacitor | 8.5.3 (`@capacitor/core`, `cli`, `ios`), Filesystem 8.1.5, Share 8.0.3, Browser 8.0.5, Geolocation 8.2.3, all pinned exactly |
| iOS packages | Swift Package Manager (no CocoaPods). `Package.resolved` is committed |
| Minimum iOS | 15.0 (Capacitor 8's minimum) |
| Devices | iPhone and iPad. AR needs world tracking (A9 chip or later); LiDAR models do better on plain walls |
| Built with | Xcode 26.3 on macOS 15.7 (Intel), iOS 26.3 SDK |

## How it fits together

```
electrical-app/                  the PWA, unchanged by the build
  js/lib/ar-measure.js           AR tape: native plugin first, then WebXR, then "not available"
  js/lib/native.js               iOS app only: files + share sheet, Keychain, window.print()
  js/session.js                  API calls: cookie on the web, API origin + Bearer token in the app
  js/ui.js  download()           calls native.js inside the app (WKWebView ignores <a download>)
mobile/
  package.json, package-lock.json
  capacitor.config.json          appId, appName, webDir: www
  scripts/copy-web.mjs           electrical-app/ -> www/ (no tests/, no sw.js, refuses secrets)
  scripts/web-config.mjs         the API origin for this build -> www/config.js (npm test)
  www/                           generated, gitignored
  ios/App/App.xcodeproj          generated by `npx cap add ios`, then edited (below)
  ios/App/App/
    MainViewController.swift     CAPBridgeViewController subclass: registers our three plugins
    SceneDelegate.swift          uses MainViewController (so does Main.storyboard)
    FishtapeMeasure/
      FishtapeMeasurePlugin.swift   the plugin: isAvailable(), measurePath()
      MeasureViewController.swift   the full-screen AR view
      MeasureFormat.swift           metric / feet-inches labels, same rules as js/lib/units.js
    Plugins/
      FishtapeKeychainPlugin.swift  get/set/remove the session and device tokens
      FishtapePrintPlugin.swift     print the web view with the iOS print sheet
      FishtapeGeofencePlugin.swift  job-site regions + significant changes while clocked in (and FishtapeLocationMonitor)
    Info.plist                   camera text, Files access, ARKit not required
    Assets.xcassets              app icon and launch image drawn from electrical-app/icons/icon.svg
    public/                      generated by `cap sync` from www/, gitignored
  ios/App/CapApp-SPM/Package.swift   written by `cap sync`: Capacitor + plugin packages
```

- **The web app ships inside the app.** `cap sync` copies `www/` into the app bundle and the app
  loads it from `capacitor://localhost`. No remote URL is loaded (`server.url` is not set), so the
  app opens and works offline from the first launch, the same as the PWA's offline field tools.
- **No service worker.** WKWebView doesn't run service workers for `capacitor://` pages and the bundle
  is already offline, so `copy-web.mjs` leaves `sw.js` out. `app.js` registers it inside a `.catch()`
  and `'serviceWorker' in navigator` is false in the app anyway (checked in the Simulator), so
  nothing breaks.
- **Plugins without a bundler.** The PWA has no build step, so it can't `import` from `@capacitor/*`.
  It doesn't need to: the native bridge puts every registered plugin on `window.Capacitor.Plugins`
  before the page loads (`FishtapeMeasure`, `FishtapeKeychain`, `FishtapePrint`, `Filesystem`, `Share`, `Browser`,
  plus Capacitor's built-ins), and `window.Capacitor.isNativePlatform()` is true.
- **Local plugin registration.** Our plugins live in the App target, so `cap sync` doesn't know about
  them. `MainViewController.capacitorDidLoad()` registers each with
  `bridge?.registerPluginInstance(...)`, Capacitor's documented way for plugins inside the app. npm
  plugins (Filesystem, Share, Browser) are registered by Capacitor from `packageClassList`.
- **Sign-in and the API.** See [Sign-in and the API](#sign-in-and-the-api).
- **Printing.** WKWebView ignores `window.print()`. In the app, `js/lib/native.js` replaces it with a
  call to `FishtapePrint`, which opens the iOS print sheet on the live web view (`@media print`
  applies; the sheet's share button saves a PDF). Screens print the browser way (mount a print-only
  copy, call `print()`, remove the copy on `afterprint` or with `setTimeout(done, …)`), so the
  replacement holds timers set in the rest of the calling task until the sheet closes and fires
  `beforeprint`/`afterprint` around it. Estimates, invoices, bending sheets, the panel directory,
  SOPs and wire runs all print without changes to their modules.
- **Files.** In the app, every `ui.download()` (wire run PDF and CSV, timesheet CSV, price book CSV,
  backups, drawing PNG/SVG exports) writes the file to the app's Documents folder and opens the share
  sheet: Save to Files, AirDrop, Mail, Messages, Print. `UIFileSharingEnabled` and
  `LSSupportsOpeningDocumentsInPlace` make that folder visible in the Files app under Fishtape.
  On the wire run screen the separate **Share PDF** button is hidden because **Download PDF**
  already shares.
- **Safe areas.** `css/app.css` ends with a safe-area block (notch, Dynamic Island, home indicator)
  for the shell, sheets, toasts and the wheel. `env(safe-area-inset-*)` is 0 in desktop browsers, so
  only the iOS app and the home-screen PWA change.
- **Data leakage rule.** `copy-web.mjs` stops if anything in `electrical-app/` looks like a secret
  (`.env*`, `.pem`, `.p8`, `.p12`, `.key`, `.mobileprovision`, `.cer`, or "secret" in the path).
  No API keys, App Store Connect keys or signing files are in the repo or the app bundle.

## Sign-in and the API

The PWA is served with the API on one origin and signs in with an httpOnly `ft_session` cookie. The
app's pages come from `capacitor://localhost`, a different origin, so relative `/api/...` URLs and
that cookie can't work there. In the app (and only there; the web path is unchanged):

- **API origin.** `npm run sync` writes `www/config.js` (`window.FISHTAPE_API_BASE`,
  `window.FISHTAPE_ENV`) and loads it before `js/app.js`. Every API call in the PWA goes through
  `apiFetch()` in `js/session.js`, which prefixes it: `api.*`/`request()`, billing (`modules/billing.js`),
  integrations (`modules/integrations.js`) and the AI assistant (`js/lib/assistant-api.js`, including
  the streamed chat reply). A new screen that calls the API must use `api.*` or `apiFetch()`, never a
  bare `fetch('/api/…')`, or it won't work in the app.
- **Bearer tokens.** Sign-in (`/auth/login`, `/auth/signup`) and crew PIN sign-in
  (`/devices/crew/sign-in`) send `mode: 'bearer'`; the API then returns the session token in the
  body instead of setting a cookie (`server/src/routes/v1/auth.js`, `admin.js`; no server change was
  needed). Every later call sends `Authorization: Bearer <token>` with `credentials: 'omit'`.
- **Keychain, not web storage.** The token is saved with `FishtapeKeychain` (service
  `com.fishtapehq.app.auth`, account `session`, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`),
  read once per launch, and removed on sign-out. Registering a shared iPad saves the device token the
  API returns under `device`; it goes out as `X-Fishtape-Device`, and **Stop crew sign-in here**
  removes it. Only those two keys are accepted. Keychain items survive deleting the app, so the
  first launch after an install clears them.
- **CSRF.** Writes still send `X-Fishtape: 1`. The API's CSRF guard skips requests that carry a
  bearer token, and sign-in requests (no token yet) pass it because `capacitor://localhost` is in the
  API's CORS origins (`server/src/config.js` always adds it).
- **Google and Microsoft sign-in** are hidden in the app. That flow is a browser redirect that ends
  by setting a cookie; doing it in the app needs `ASWebAuthenticationSession` and a one-time code the
  app can swap for a bearer token (a server change). Hiding them also keeps App Review's rule on
  third-party sign-in (guideline 4.8) out of play for now.
- **Pages outside the app.** Stripe Checkout and the billing portal open with `openExternal()`
  (`js/lib/native.js`): this tab on the web, a Safari sheet over the app in iOS (`@capacitor/browser`),
  and Billing reloads when the sheet closes. Stripe's return page is the web app, shown in that sheet;
  people tap Done to get back. Other external links (`target="_blank"`, maps, `mailto:`) never load
  inside the app: Capacitor hands any page from another site to Safari, Maps or Mail.
- **Password reset and invite links** open the web app in Safari; after setting a password, sign in
  in the app.

`405 Not Allowed`, so until the API is live the app starts in offline mode.

## FishtapeMeasure

Contract (also in `docs/BUILD-PLAN.md` and `docs/field/wire-runs.md`):

```ts
isAvailable(): Promise<{ available: boolean }>     // ARWorldTrackingConfiguration.isSupported
measurePath({ units: 'metric' | 'imperial' }): Promise<{
  totalM: number,
  segments: { lengthM: number }[],
  points: { x: number, y: number, z: number }[],   // metres, ARKit world space
  snapshot?: string,                               // 'data:image/jpeg;base64,...', max 1280 px, ~400 KB
}>
// rejects: 'cancelled' (message and code) when the user cancels,
//          code 'camera_denied', 'unavailable', 'busy' or 'ar_failed' with a plain-English message
```

What the AR screen does:

- Full-screen `ARSCNView`, `ARWorldTrackingConfiguration` with horizontal and vertical plane
  detection. On LiDAR devices it also turns on scene reconstruction (`.mesh`), so raycasts land on
  plain drywall.
- ARKit's coaching overlay runs until a surface is found; the measuring controls hide while it shows
  (Cancel stays).
- A centre dot raycasts every frame to detected planes and estimated planes (LiDAR devices try
  estimated planes first because they follow the mesh). A ring lies flat on the surface under it; the
  2D dot is dashed while nothing is under it.
- **Add point** (big yellow button) or a tap anywhere on the camera view drops a point. Points are
  joined by yellow lines with a length label on each leg; a white live line and label run from the
  last point to the dot. The panel at the top shows the total, the live leg and a status line
  (tracking problems, "move slowly", what to do next).
- **Undo** removes the last point. **Done** needs two or more points. **Cancel** asks before
  discarding points, then rejects with `'cancelled'`.
- Labels use the user's units: `450 mm` / `3.25 m`, or feet-inches to the 1/16" (`12' 3 5/8"`).
  Returned lengths are always metres.
- Done draws the leg labels and the total onto a snapshot of the AR view, scales it to at most
  1280 px on the long side and JPEG-compresses it to about 400 KB or less.
- Built for gloves: buttons are 62 to 76 pt tall with large text, plus haptics on each point. Phones
  in landscape get the controls in a column on the right so they don't cover the dot.
- Camera permission: asked the first time. If it is off, an alert explains it and offers
  **Open Settings**, and the promise rejects with `camera_denied` and the same message (the wire run
  screen shows it as a toast).
- The screen stays awake while measuring.

ARKit is not in `UIRequiredDeviceCapabilities`, so devices without AR can install the app;
`isAvailable()` returns false there (and in the Simulator), and Wire Runs offers the plan trace and
typed lengths instead.

## FishtapeGeofence

Location while clocked in ([docs/field/timesheets.md](../field/timesheets.md),
[privacy](../compliance/privacy.md#location-while-clocked-in)). One fix at each clock change comes from
Capacitor's Geolocation plugin (`@capacitor/geolocation` 8.2.3). Arrivals and departures with the app
closed come from our plugin:

```ts
start({ shiftId, regions: [{ id, lat, lng, radiusM }] }): Promise<{ tracking, authorization }>  // refuses without a shiftId
stop(): Promise<void>                       // clock-out; also whenever the web app finds no open shift
events(): Promise<{ events: { at, type: 'enter'|'exit'|'significant', siteId?, lat?, lng?, accuracyM? }[] }>  // drained
status(): Promise<{ tracking, shiftId?, authorization }>
```

- `FishtapeLocationMonitor` (same file) owns the `CLLocationManager` and is created in
  `AppDelegate`, because iOS relaunches the app in the background for region events before any web
  view exists. Events wait in `UserDefaults` (at most 500) until the web app reads them.
- Region monitoring (nearest 18 job sites; iOS allows 20) and significant location changes only: low
  power, no continuous GPS, so no `UIBackgroundModes` entry. Needs **Always**; iOS asks While Using
  first, then the app asks for the upgrade during an open shift.
- Never without a shift: `start` needs a shift id, `stop` clears regions and unread events, and a
  shift older than 18 hours stops itself at the next launch or event.
- `Info.plist`: `NSLocationWhenInUseUsageDescription` and `NSLocationAlwaysAndWhenInUseUsageDescription`,
  both saying "only while you are clocked in". Update the App Privacy answers (precise location,
  linked to the user, app functionality) before the next TestFlight build.
- Built for the Simulator on 2026-10-20 (`npm run build:sim`: BUILD SUCCEEDED, no warnings in our
  files). Not yet tried on a device: permission prompts, background relaunch, force-quit and reboot
  behaviour need an iPhone (VERIFY).

## Build on the Mac

The Mac is `kelvin@192.168.0.9` (key auth). Everything for this app lives in `~/dev/fishtape`;
don't touch the other apps on that Mac. Node 22 is at `~/.local/node/bin`. No Homebrew or
CocoaPods is needed.

**1. Get the code there.** Until the repo is on GitHub, move it with a git bundle:

```sh
# Windows (Git Bash), in the repo
git bundle create fishtape.bundle claude/electrical-concept-app-h4qz12
scp fishtape.bundle kelvin@192.168.0.9:dev/fishtape/bundles/

# Mac: first time
cd ~/dev/fishtape && git clone -b claude/electrical-concept-app-h4qz12 bundles/fishtape.bundle repo
# Mac: later
cd ~/dev/fishtape/repo && git pull --ff-only ../bundles/fishtape.bundle claude/electrical-concept-app-h4qz12
```

Bring Mac-made changes back with `git format-patch` or `scp`, and commit them on Windows.

**2. Install, copy the web app, sync:**

```sh
export PATH=$HOME/.local/node/bin:$PATH
cd ~/dev/fishtape/repo/mobile
npm ci
npm test              # web-config.mjs checks
npm run sync          # copy-web.mjs (+ www/config.js for staging), then cap sync ios
FISHTAPE_ENV=production npm run sync   # when production is live
```

Run `npm run sync` after every change to `electrical-app/`. It rewrites `ios/App/App/public`,
`capacitor.config.json` and `config.xml` inside the iOS project (all gitignored) and
`CapApp-SPM/Package.swift` (committed, only changes when plugins change).

**3. Build.** From `mobile/`:

```sh
DERIVED_DATA_PATH=~/dev/fishtape/.derived npm run build:sim      # Simulator, Debug
DERIVED_DATA_PATH=~/dev/fishtape/.derived npm run build:device   # device, Release, unsigned
```

which run:

```sh
cd ios/App   # (the npm scripts pass -project ios/App/App.xcodeproj instead)
xcodebuild -project App.xcodeproj -scheme App -configuration Debug \
  -destination 'generic/platform=iOS Simulator' -derivedDataPath ~/dev/fishtape/.derived build
xcodebuild -project App.xcodeproj -scheme App -configuration Release \
  -destination 'generic/platform=iOS' -derivedDataPath ~/dev/fishtape/.derived CODE_SIGNING_ALLOWED=NO build
```

The first build fetches `capacitor-swift-pm` and `ion-ios-filesystem` from GitHub into the derived
data folder. Both builds succeed with no errors and no warnings in our code (2026-10-19, with the
Keychain and print plugins).

**Simulator check.** Boot a simulator, install
`~/dev/fishtape/.derived/Build/Products/Debug-iphonesimulator/App.app` with `xcrun simctl install`,
and launch it with `xcrun simctl launch --console-pty <udid> com.fishtapehq.app` to see the bridge
log (`⚡️ To Native -> FishtapeMeasure isAvailable`, `TO JS {"available":false}`). Use a throwaway
simulator (`xcrun simctl create`, then `delete`) so Kelvin's own simulators stay as they are.

## Signing and TestFlight

**Now one command on the Mac** (team `9C68LPL6JA`, app record "FishTapeHQ", bundle ID registered):

```sh
cd ~/dev/fishtape/repo && mobile/scripts/testflight.sh
```

It syncs against production (`https://app.fishtapehq.com`), archives with build number
`YYYYMMDDHHMM` (UTC) and marketing version 1.0, signs and uploads with `mobile/ios/ExportOptions.plist`
and the API key in `~/.appstoreconnect/api_key.json` (read inside the script, never printed), waits
for processing (`mobile/scripts/asc.mjs wait-build`) and puts the build in the internal TestFlight
group "TG Electrical" (`asc.mjs testflight`, created if missing). Logs go to `~/dev/fishtape/build/`.

- The archive is unsigned on purpose: automatic signing at archive time wants a development profile,
  which needs a registered device. The export signs for App Store distribution instead.
- **Signing needs the login keychain unlocked.** Over SSH it is locked and codesign fails with
  `errSecInternalComponent`. Run the script in Terminal on the Mac itself, or unlock first with
  `security unlock-keychain ~/Library/Keychains/login.keychain-db` (asks for the Mac password). The
  first time, macOS may ask to let `codesign` use the distribution key: choose **Always Allow**.
- `ITSAppUsesNonExemptEncryption = NO` is in `Info.plist`, so uploads skip the export-compliance
  question.

The steps below are what the script does, for reference.

1. **Team.** Set `DEVELOPMENT_TEAM` for the App target (Xcode, or `DEVELOPMENT_TEAM = <TEAM_ID>;` in
   both App build configurations of `project.pbxproj`). Leave `CODE_SIGN_STYLE = Automatic`.
2. **Bundle ID.** Register `com.fishtapehq.app` (Certificates, Identifiers & Profiles, or the
   App Store Connect API `POST /v1/bundleIds`). With automatic signing and an API key,
   `-allowProvisioningUpdates` also registers it on the first archive. No extra capabilities are
   needed: ARKit, the camera and the Files folder need no entitlements.
3. **App record.** App Store Connect > Apps > New App: iOS, name Fishtape (or the final name once
   the CIPO check is done), bundle ID `com.fishtapehq.app`, SKU e.g. `fishtape-ios`.
4. **Archive and upload** on the Mac:

   ```sh
   cd ~/dev/fishtape/repo/mobile && npm run sync
   KEY=~/.appstoreconnect/private_keys/AuthKey_<KEY_ID>.p8
   AUTH="-allowProvisioningUpdates -authenticationKeyPath $KEY -authenticationKeyID <KEY_ID> -authenticationKeyIssuerID <ISSUER_ID>"
   xcodebuild -project ios/App/App.xcodeproj -scheme App -configuration Release \
     -destination 'generic/platform=iOS' -archivePath ~/dev/fishtape/Fishtape.xcarchive \
     DEVELOPMENT_TEAM=<TEAM_ID> $AUTH archive
   xcodebuild -exportArchive -archivePath ~/dev/fishtape/Fishtape.xcarchive \
     -exportOptionsPlist ~/dev/fishtape/ExportOptions.plist -exportPath ~/dev/fishtape/export $AUTH
   ```

   with `~/dev/fishtape/ExportOptions.plist` (outside the repo):

   ```xml
   <?xml version="1.0" encoding="UTF-8"?>
   <!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
   <plist version="1.0"><dict>
     <key>method</key><string>app-store-connect</string>
     <key>destination</key><string>upload</string>
     <key>teamID</key><string>TEAM_ID</string>
     <key>signingStyle</key><string>automatic</string>
   </dict></plist>
   ```

5. **Versions.** Bump `CURRENT_PROJECT_VERSION` (build number) for every upload and
   `MARKETING_VERSION` (1.0, 1.1, …) for each release, in the App target's build settings.
6. **Before the first TestFlight build:** decide the export-compliance answer (the app only uses
   HTTPS, so `ITSAppUsesNonExemptEncryption = NO` in `Info.plist` is the usual answer and skips the
   question on every upload; Kelvin to confirm), fill in the App Privacy questionnaire, add a privacy
   policy URL, and add internal testers.

## App Store review risks

**Guideline 4.2 (Minimum Functionality)** is the main risk for a web app in a native wrapper: Apple
rejects apps that are "a repackaged website" or don't feel like an app. What Fishtape has that a
website doesn't:

| native feature | why it counts |
| --- | --- |
| ARKit tape measure (`FishtapeMeasure`) | Full native ARKit/SceneKit screen with coaching, LiDAR mesh, haptics. Not possible in Safari on iOS. Make it the first thing in the review notes and the screenshots. |
| Works offline from the bundle | The whole app ships inside the binary and runs with no network: time clock, drawings, calculators, pipe bending, wire runs. No remote web content is loaded. |
| Camera | AR measuring and job photos (the photo picker offers the camera). |
| Files and share sheet | PDFs and CSVs saved to the Files app, AirDrop, Mail, Print. |
| Field-ready UI | Large touch targets, haptics, iPad layout, landscape. |

Other review points:

- **2.1 App completeness.** Every button must do something. Downloads go to the share sheet and
  every Print button opens the iOS print sheet (both checked in the Simulator).
- **Sign-in.** App Review needs a working demo account (a seeded test company on the API the build
  points at) in the review notes, and that API must be up during review. Google and Microsoft
  sign-in are hidden in the app, so guideline 4.8 (an equivalent privacy-focused login option next
  to third-party sign-in) doesn't apply yet. If they come to the app later, add Sign in with Apple
  or confirm an exception applies (check the current wording).
- **Account deletion.** Apps that let people create an account must let them delete it in the app
  (guideline 5.1.1(v)). The app doesn't offer sign-up today; if it does, add "Delete account".
- **5.1.1 Privacy.** The camera text says what it's for. If the app later uploads photos or
  location, add the matching purpose strings and update the App Privacy answers.
- **Payments (guideline 3.1), a real risk.** Customers paying a contractor's invoice with Stripe is
  payment for real-world services, which in-app purchase rules don't cover. Fishtape's own plans are
  different: the Billing screen (owners and admins) opens Stripe Checkout and the customer portal,
  and in the app those open in a Safari sheet. Apple generally requires in-app purchase for digital
  subscriptions sold in an iOS app, and outside the US storefront doesn't allow buttons or links to
  other ways of paying. Fishtape is sold to companies for their crews, which may fit the
  "enterprise services" exception (3.1.3(c)), but that is Apple's call. Options before submitting:
  hide the plan purchase and portal buttons in the iOS app (show the current plan only), argue
  3.1.3(c) in the review notes, or add in-app purchase. Kelvin to decide.
- **Placeholder content.** The icon and launch image are Fishtape's own, drawn from
  `electrical-app/icons/icon.svg` (the Capacitor placeholders are gone). Seeded demo data should not
  appear in the review build's screenshots as if it were real customers.

## Known limits and follow-ups

- **AR is untested on hardware.** It compiles for device and the Simulator, and `isAvailable()`
  returns false in the Simulator without crashing, but the AR screen itself (tracking, raycasts,
  labels, snapshot, permission prompt) needs a run on a real iPhone or iPad. Accuracy numbers in
  `docs/field/wire-runs.md` are still marked VERIFY.
- **Status bar colour.** It follows the system light/dark setting. If someone picks the dark theme
  in Fishtape while the phone is in light mode, the status bar text stays dark. The fix is a call to
  `Capacitor.Plugins.SystemBars.setStyle()` when the theme changes (`js/app.js`).
- **Web storage.** The app's IndexedDB and localStorage live in the WKWebView store for
  `capacitor://localhost`. It is persistent, but iOS can clear website data under heavy storage
  pressure; sync makes the server the source of truth. Sign-in tokens are in the Keychain, not
  there.
- **Sign-in against a real API is untested.** The flow is covered by Node tests with a fake API
  (`electrical-app/tests/session-native.test.mjs`) and the server's own bearer, CORS and crew PIN
  tests, and the Keychain plugin was checked in the Simulator, but staging has no API yet (see
  [API origin](#api-origin)).
- **Printing on paper** is untested; the Simulator shows the print sheet with the page.
