# Panel schedule print & label (S27)

What TG Electric asked for on the panel schedule, built on top of the tandem support (S26).
All changes are additive to the panel schema and settings; existing panels keep working, and the
printout stays fluid (full width, capped at 7.5in — no fixed width that clips).

## What shipped

1. **Offline QR panel label.** Each panel prints a QR that encodes the canonical deep link to that
   panel (`BRAND.appOrigin` + `/#/panels/<id>`, falling back to `location.origin`), so scanning it a
   year later reopens the panel to view, edit or reprint. The encoder is **vendored** (Kazuhiko
   Arase `qrcode-generator` 2.0.4, MIT) at `electrical-app/vendor/qrcode-generator-2.0.4/` with its
   `LICENSE`; it is pure JS, no `eval`, no network, no external script. We read the module matrix
   and draw the QR as **inline SVG** (`js/lib/qr.js`: `panelUrl`, `qrMatrix`, `qrSvg`, `qrSvgNode`) —
   never the library's own `createSvgTag` (that emits inline `style=""`, which the CSP blocks). The
   QR shows on the directory header, on an on-screen "Panel label" sticker card, and on a dedicated
   label print (the "Panel label" action), sized to print and stick inside the panel door.

2. **Colour bands.** `bandIndexBySlot()` assigns an alternating band (0/1) to every space, computed
   down each column, so a multi-pole breaker's spaces are one band and two tandems in a space share
   the space's band. Band colours are configurable per company (`settings.panelPrint.bandColors`,
   default a photocopy-safe faint grey / white). Applied in print; the swatch legend is unchanged.

3. **Smoke / purpose highlight.** A per-circuit free `purpose` tag; `smoke`/`alarm` highlight red by
   default (`settings.panelPrint.smokeColor`). Editable per circuit via `colorOverride`, now extended
   to accept a `#rrggbb` highlight or the literal `none` (a phase key still means the swatch override).
   `highlightFor()` resolves it. The highlight is a left border + coloured text, so it reads on top of
   the band background rather than fighting it.

4. **Breaker-size toggle.** `settings.panelPrint.showAmps` shows or hides the AMP column on screen
   chips and the printed directory (the columns collapse from DESC/CCT/AMP to DESC/CCT when off).

5. **Fill-as-you-go progress.** A per-circuit `status` (`planned | rough-in | connected | tested |
   done`, optional, empty = not tracked) shown as a small chip with an inline quick-set select, plus a
   panel **completion** indicator (`completion()`: % of described circuits marked done) at the top of
   the editor, on the label and on the directory header. `settings.panelPrint.showStatus` ties whether
   status prints.

6. **Exact two-column layout.** Left half DESCRIPTION | CCT. | AMP facing a centre rule the right half
   mirrors (AMP | CCT. | DESCRIPTION); A/B circuit numbers for tandems; the breaker amp/type shown once
   per breaker with a breaker-type annotation (AFCI/GFCI/…); a header block (name, location, service =
   voltage + main + bus); the colour bands; the smoke highlight; and a footer with the company logo,
   website, email and phone pulled from company settings (same `settings.company` the invoices use).

## Tandem follow-ups (from the S26 review)

- **Make full-space** — `makeFullSpace()` converts a tandem back to a full breaker when its sibling
  half is empty (clears `half`); offered in the breaker options sheet.
- **A/B labels in warnings** — the over-80% hot-breaker list appends `halfOf(c)` so two tandems in one
  space are distinguishable.
- **No-neutral systems** — tandem breaker templates are hidden in the template picker when the system
  has no neutral, matching the empty-cell UI that already hides the Tandem button.

## Schema / settings (all additive)

- **panel:** `location` (string ≤200).
- **circuit:** `purpose` (string ≤40), `status` (enum, empty default); `colorOverride` extended to a
  `#rrggbb` highlight or `none`.
- **settings.panelPrint** (new): `bandColors: ["#eef2f7","#ffffff"]`, `showAmps: true`,
  `showStatus: false`, `smokeColor: "#e2231a"`.
- **settings.company:** `website` added (`name/phone/email/logo` already existed).
- **brand.js:** `appOrigin: "https://app.fishtapehq.com"`.

## Note on the QR library

The architect's contract named Nayuki "QR Code generator" v1.8.0 at
`typescript-javascript/qrcodegen.js`. That tag ships only the TypeScript source — the `.js` is
generated by a build step, so there is no stable file to vendor verbatim. The contract's named
alternative, Kazuhiko Arase `qrcode-generator`, ships a ready **ES-module** build (`dist/qrcode.mjs`)
on npm that is pure, eval-free and exposes `getModuleCount()` / `isDark()`, so it was vendored
instead, verbatim and pinned at 2.0.4. Same offline, CSP-safe, inline-SVG result.
